Build a full-stack web application called **RedPath Sentinel**.

This project is a portfolio cybersecurity tool that combines a mini BloodHound-style graph, an identity attack path simulator, an Nmap scan visualizer, and a red team difficulty scoring system. The goal is to show how blue team IAM knowledge can be used to understand red team attack paths in a safe homelab environment.

The application should be safe, educational, and defensive. Do not include exploit commands, malware, credential theft, real attack automation, or instructions to compromise real systems. The app should identify possible weaknesses, explain why they matter, and provide blue team remediation guidance.

Use Replit-friendly technologies:

* Frontend: React + TypeScript
* Backend: Node.js + Express
* Styling: Tailwind CSS or clean CSS
* Graph library: React Flow, Cytoscape.js, or another interactive graph library
* Data storage: local JSON files or SQLite
* File upload support for Nmap XML files

Main application name:
**RedPath Sentinel**

Purpose:
Create an interactive cybersecurity dashboard where a user can upload an Nmap XML scan from a homelab, visualize hosts and services as nodes in a graph, click each host to view details, see possible weaknesses, receive a red team difficulty score, and simulate identity-based attack paths between a starting identity and a target system.

Core pages/features:

1. **Dashboard Overview**
   Create a main dashboard with summary cards:

* Total hosts discovered
* Total open ports
* High-risk services
* Identity risks found
* Easy targets
* Medium targets
* Hard targets
* Total possible attack paths

2. **Nmap XML Upload**
   Create an upload page or upload section where the user can upload an Nmap XML file.

The app should parse the Nmap XML and extract:

* IP address
* Hostname if available
* Host status
* Open ports
* Protocol
* Service name
* Product/version if available
* OS guess if available
* MAC address if available

After upload, store the parsed scan data in app state and/or local JSON/SQLite storage.

3. **Interactive Graph View**
   Create a mini BloodHound-style interactive graph.

The graph should show:

* Host nodes
* Service/port nodes
* Identity/user nodes
* Group nodes
* Privilege/risk nodes
* Target nodes

Suggested node types:

* Host
* Service
* User
* Group
* Admin
* Weakness
* Target

Suggested edges:

* Host “exposes” Service
* Service “may indicate” Weakness
* User “member of” Group
* Group “has access to” Host
* User “can authenticate to” Host
* Weakness “increases risk of” Host
* Host “path to” Target

Make the graph interactive:

* User can click a node
* A side details panel opens
* The selected node is highlighted
* The panel shows details, weaknesses, difficulty score, and defensive recommendations

4. **Host Details Panel**
   When a host node is clicked, show:

* IP address
* Hostname
* OS guess
* Open ports
* Services
* Service versions
* Risk observations
* Possible weaknesses
* Red team difficulty score
* Blue team recommendations

Example weakness mapping:

* Port 22 SSH: Check for key-based authentication, disable password login if possible, review failed login attempts, enforce MFA where possible
* Port 80/443 HTTP/HTTPS: Check default pages, outdated software, weak TLS, exposed admin panels
* Port 445 SMB: Check SMB signing, guest access, share permissions, outdated Windows systems
* Port 3389 RDP: Check exposure, MFA, account lockout policy, restricted admin access
* Port 389/636 LDAP/LDAPS: Check anonymous binds, LDAP signing, domain exposure
* Port 53 DNS: Check zone transfer, recursion settings, DNS misconfiguration
* Port 21 FTP: Check anonymous login, cleartext credentials, outdated FTP service
* Port 3306 MySQL / 5432 PostgreSQL / 1433 MSSQL: Check exposed database access, weak authentication, unnecessary exposure

Do not provide exploitation commands. Only provide risk explanations and defensive checks.

5. **Red Team Difficulty Score**
   Create a scoring engine that labels each host as:

* Easy
* Medium
* Hard

The score should be based on:

* Number of open ports
* Presence of high-risk services
* Exposed remote access services
* Missing MFA flag from identity data
* Privileged users linked to the host
* Dormant accounts linked to the host
* Service accounts linked to the host
* Whether the host appears to be a domain controller, server, workstation, or unknown

Example scoring logic:

* Easy: multiple high-risk services, remote access exposed, weak IAM conditions, privileged/dormant accounts linked
* Medium: some risky services and some IAM risk
* Hard: few exposed services, no obvious IAM risk, MFA enabled, least privilege

Show the score visually in the UI and explain why the score was assigned.

6. **Identity Attack Path Simulator**
   Create a page or section called **Identity Attack Path Simulator**.

The user should be able to select:

* Starting identity
* Target host or target privilege level

Example starting identities:

* Low Privilege User
* Helpdesk User
* Dormant Account
* Service Account
* Local Admin
* Domain Admin

Example target:

* Workstation
* File Server
* Domain Controller
* Admin Group
* Sensitive Application

The app should generate a simulated attack path based on graph relationships and risk rules.

Example safe path output:
“Dormant Account → Member of Helpdesk Group → Can reset passwords → Has access to File Server → File Server has SMB exposed → Possible path to Sensitive Data”

The app should explain:

* Why the path matters
* Which identity/control weaknesses are involved
* How a defender could reduce the risk

Do not include real exploitation steps.

8. **Weakness Rule Engine**
   Create a simple rules file or rules object that maps ports/services to security observations.

Each rule should include:

* Port
* Service
* Risk level
* Observation
* Why it matters
* Blue team recommendation

Example:
Port 445 / SMB:
Risk level: High
Observation: SMB is exposed.
Why it matters: SMB can expose file shares and may reveal sensitive access paths if permissions are weak.
Recommendation: Review share permissions, require SMB signing, disable guest access, patch Windows systems, and restrict access.
